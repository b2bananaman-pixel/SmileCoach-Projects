## 1. サービス概要（※最後に書いてOK）
Smile Coach
AIが接客の基本をコーチングするトレーニングアプリ


- このサービスはどんなサービスか（3行以内）
Smile Coachは、接客未経験の新人がAIからフィードバックを受けながら、一人で接客練習ができるAI接客トレーニングサービスです。
接客練習を録画し、AIが話し方や接客内容を分析することで、自分の改善点を客観的に確認できます。


- 誰の、どんな課題を、どう解決するか
対象ユーザー
家電量販店や通信販売、コールセンターなどの提案型接客に携わる、接客未経験の新人社員。

課題
新人社員は、実際のお客様対応をする前に

笑顔で話せているか
聞き取りやすい話し方ができているか
相手に安心感を与えられているか

など、自分の接客の良し悪しを客観的に確認する機会が少ないという課題があります。
また、教育担当者が常に練習に付き添うことは難しく、十分な練習量を確保できない場合があります。

解決方法
Smile Coachでは、ブラウザ上で接客練習を録画し、AIによる文字起こしとフィードバックを行います。

ユーザーは、
良かった点
改善ポイント
次回意識すること

を確認しながら、自分のペースで繰り返し練習できます。
これにより、接客未経験の新人が不安を減らし、自信を持ってお客様対応ができる状態を目指します。

## 2. このアイデアはどこから生まれたか
コールセンターや家電量販店で接客業務を経験から

### 2-1. きっかけとなった体験・感情
コールセンターや家電量販店で接客業務を経験する中で、お客様に与える第一印象の重要性を強く感じました。
笑顔や話し方が良いだけで、お客様が安心して話を聞いてくださる場面を何度も経験しました。
一方で、新人教育では「もっと笑顔で」「もう少しゆっくり話して」といった感覚的なアドバイスが多く、自分自身も「どのくらい笑えているのか」「本当に改善できているのか」を客観的に確認する方法がありませんでした。
そこで、AIを活用して接客を客観的に分析し、一人でも接客の基本を練習できるサービスを作りたいと考えました。

### 2-2. なぜそれが「気になった」のか
私は、お客様に安心して相談していただける接客を大切にしています。
そのためには商品知識だけでなく、笑顔や話し方などの基本的な接客態度が重要だと考えています。
しかし、接客態度は数値化しにくく、「もっと笑顔で」「もっとゆっくり話して」といった曖昧なアドバイスになりやすいことに以前から違和感を感じていました。
また、自分自身も接客経験を積む中で、「客観的に自分の接客を振り返ることができれば、もっと早く成長できたのではないか」と感じる場面がありました。
そのため、AIを活用して接客を客観的に分析し、誰でも一人で基本的な接客を練習できる環境を作りたいと考えました。

## 8. このアプリの懸念点とその対策
※最低1つは必ず書いてください。

このアプリが**うまくいかない可能性**と、
それに対して**どう向き合おうとしているか**を書いてください。

### 懸念点①

録画・録音データを保存することへの心理的抵抗
何が問題になりそうか：
接客練習ではユーザー自身の顔や声を録画するため、「自分の動画や音声が残ること」に不安を感じるユーザーがいる可能性があります。

特に新人社員の場合、未熟な接客を記録されることへの抵抗感があり、練習自体をためらってしまう可能性があります。

なぜそう思うか：
接客練習は本来、失敗しながら改善するためのものですが、録画データが残ることで「評価されるもの」と感じてしまうと、自然な練習ができなくなる可能性があります。

そのために考えている対策：
MVPでは、AI分析に必要なデータのみを利用し、分析完了後に動画・音声データを自動削除できる仕組みを検討します。

また、ユーザーが安心して利用できるように、データの保存期間や利用目的を明確に表示します。
将来的には、ユーザー自身が

保存する
ダウンロード後に削除する
自動削除する

などを選択できる機能を追加します。

懸念点②
AIによる評価が必ずしも正確ではない可能性
何が問題になりそうか：
AIによる接客評価は、人間の教育担当者による評価と完全に一致するとは限らず、適切ではないフィードバックを行う可能性があります。

なぜそう思うか：
接客には状況や相手によって正解が変わる部分があり、表情や話し方だけでは判断できない要素もあります。

そのために考えている対策：
AIを「合否を判断するもの」ではなく、「改善のきっかけを提供するコーチ」として位置づけます。
また、評価結果だけではなく、

良かった点
改善ポイント
次回意識すること

を提示することで、ユーザーが前向きに改善できる仕組みにします。

懸念点③
AI API利用によるコスト
何が問題になりそうか：
音声文字起こしやAIコメント生成には外部APIを利用するため、利用者が増えた場合にAPI利用料が発生します。
なぜそう思うか：
動画や音声データはテキストデータと比較して処理量が大きく、利用回数によってコストが増加する可能性があります。
そのために考えている対策：
MVPでは利用回数を制限し、必要な分析のみを実行することでコストを管理します。
また、本リリースでは利用状況に応じた料金プランや企業向けプランなどを検討します。

## 10. 技術スタック（手段としての技術）
### 10-1. 使用予定の技術

フレームワーク
Ruby on Rails 8

理由：
ユーザー管理、データ保存、認証機能、CRUD機能など、Webアプリケーション開発に必要な機能を効率よく実装できるため採用します。

また、これまで学習してきたRailsの知識を活かし、サービスの価値提供部分であるAI連携や接客分析機能の開発に時間を使うためです。

フロントエンド
HTML
CSS
JavaScript
Hotwire（Turbo / Stimulus）

理由：卒業制作では高速な開発と完成度を重視し、Rails標準のHotwireを利用します。

ページ遷移や一部画面更新を高速化しながら、JavaScriptの複雑な実装を減らし、Railsとの親和性を活かした開発を行います。

データベース
PostgreSQL

理由：Railsとの相性が良く、ユーザー情報や接客練習履歴、AI分析結果などの関連データを安全に管理できるため採用します。

認証
Devise

理由：ユーザー登録、ログイン、パスワード管理などの認証機能を効率的に実装でき、開発期間を短縮できるため採用します。

AI・外部サービス
音声文字起こし
Whisper API

利用目的：録音した接客練習データを文字起こしし、AI分析に利用します。

AIフィードバック生成
OpenAI API

利用目的：文字起こし結果や接客内容を分析し、改善コメントを生成します。

録画
MediaRecorder API

利用目的：
ブラウザ上でユーザーの動画・音声を取得します。

### 10-2. 技術選定の比較検討

候補	採用/不採用	理由
Ruby on Rails	採用	学習経験があり、認証・DB操作・CRUD機能を効率的に実装できるため
React	不採用（将来検討）	高度なUIを作成できるが、MVPではRailsとの連携部分に集中するため
Vue.js	不採用	フロントエンド開発の学習コストが増え、MVP開発期間を考慮したため
Node.js	不採用	バックエンドとフロントエンドで技術が分かれ、今回の規模ではRails単体の方が効率的なため
PostgreSQL	採用	Railsとの相性が良く、複数テーブルの関連管理に適しているため

不安な点
AI分析の精度

AIによる評価が、必ずしも人間の感じる接客評価と一致するとは限らない点が不安です。
そのため、MVPではAIを合否判定ではなく、改善のきっかけを提供するコーチとして利用します。

動画・音声処理の実装

録画、アップロード、AI処理など、これまで経験していない技術領域があります。
そのため、まずは音声文字起こしとAIコメント生成を優先し、段階的に機能追加を行います。


### 10-3.キャッチアップ不足の懸念

今回の開発では、これまで学習してきたRuby on Railsの知識に加えて、AI API連携や動画・音声データ処理など、新しく学習が必要な技術があります。

特に以下の点については、実装時にキャッチアップが必要だと考えています。

① AI API連携
懸念点：

OpenAI APIやWhisper APIなど、外部サービスとの連携経験が少なく、APIへのリクエスト処理やエラーハンドリングについて理解を深める必要があります。

対策：

まずは小さな検証アプリを作成し、

APIへのリクエスト方法
レスポンスデータの取得
Railsへの保存方法

を確認した上で、本アプリへ組み込みます。

② 動画・音声データの扱い
懸念点：

MediaRecorder APIを利用した録画、ファイルアップロード、保存、削除処理など、通常のテキストデータとは異なるデータ管理が必要になります。

対策：

MVPでは機能を絞り、

ブラウザで録音する
音声ファイルを保存する
Whisper APIへ送信する
分析結果を保存する

という最小構成から実装します。

また、動画保存や高度な解析機能については、本リリースに向けて段階的に追加します。

③ JavaScript・フロントエンド処理
懸念点：

Rails開発ではサーバーサイドを中心に学習してきたため、ブラウザの録画制御や非同期処理などJavaScriptの知識が不足しています。

対策：

必要な範囲に絞ってJavaScriptを学習し、MediaRecorder APIなど今回必要な機能から優先的に実装します。

④ AI分析結果の設計
懸念点：

AIから取得した文章をどのように評価結果として保存・表示するか、ユーザーにとって分かりやすい形に設計する必要があります。

対策：

まずは、

良かった点
改善ポイント
次回意識すること

というシンプルな形式で実装し、利用者の反応を見ながら改善します。

今回の開発で意識すること

新しい技術をすべて完璧に理解してから開発するのではなく、サービスに必要な範囲を見極め、検証しながら段階的に実装を進めます。

MVPでは「接客練習を録画し、AIから改善フィードバックを受けられる」というサービス価値を最優先し、技術的な挑戦とのバランスを取りながら開発します。
